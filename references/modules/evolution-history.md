# Evolution History

## Goal

Recover `initial state → first implementation → discovered limitation → redesign/migration → current state`, including pre-repository evidence limits.

## Applicability and depth

Enable for iterated, migrated, or maintained work. N/A applies only to a genuinely single-state artifact.

- **Brief:** inspect README, changelog, tags, and overview for phases.
- **Standard:** inspect chronology, renamed files, releases, examples, and migration docs.
- **Deep:** inspect older variants, tags/branches, diffs, abandoned artifacts, and testimony; reconcile chronology conflicts and recover each transition trigger.

## Facts, interview, and rendering

Record phase, date/window, change, trigger, source, consequence, and ownership. Ask what existed before, what prompted the transition, and what changed after it. Do not treat repository creation date as project inception or commit count as iteration depth; render chronology and preserve unknown earlier stages.
